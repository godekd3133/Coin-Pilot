# 실거래 평가액 표시 복구 — 2026-10-08

소량의 GAS 때문에 실계좌 전체 평가액이 확인 불가로 표시되는 문제를 재현하고 운영 LIVE 서버에 반영했다. 개인 잔액·수량 및 인증 정보는 이 기록에 저장하지 않는다.

원인: 계좌 평가에 주문 실행용의 90초 체결 시각 조건을 적용했다. 거래가 뜸한 GAS의 마지막 체결이 오래되면, 정상적인 최신 API 조회에서도 계좌 전체 평가액을 막았다. 티커 생성 시각도 조용한 시장에서 항상 갱신되지는 않아 이것만으로 문제를 해결할 수 없었다. 또한 이전 운영 /positions 코드는 Map을 객체 인덱스로 읽었고, /account는 전략에 포함되지 않은 실계좌 잔여 코인을 목록에서 빠뜨렸다.

수정: 평가 조회에서 최신 티커 생성 시각 또는 명시적 메타데이터가 있는 최근 성공한 upstream 시세 스냅샷을 사용한다. 원래 가격 시각(sourceAsOf)과 조회 시각(fetchedAt)을 구분해 유지한다. 명시적 조회 메타데이터가 없는 자료, 오래된 조회, 잘못된/미래 원본 시각, 잘못된 가격, last_good 디스크 대체 값은 평가 근거로 승격하지 않는다. 평균 매수가로 평가액을 채우지 않는다. 자동 주문과 위험 감시의 마지막 체결 시각 검사는 변경하지 않았다. 공용 캐시는 티커 생성 시각을 체결 시각과 별도로 보존한다.

LIVE 원본을 읽고 해시를 검사한 뒤 marketValuation.js, publicMarketSnapshotStore.js, routes/account.js 세 파일만 반영했다. /positions의 Map 조회를 수정했고, /account는 실제 거래소 보유 잔액을 표시한다. 조회 목록을 추가해도 전략의 관리 포지션을 생성하지 않음을 테스트했다. 모의 서버와 투자 설정은 변경하지 않았다. 재시작 후 기존 자동매매 ON 선택도 복원됐다.

검증: 관련 최종 테스트 50개, 배포된 실제 계좌 라우트의 격리된 가짜 계좌/시세 검사 6개 통과. 최근 upstream 조회의 오래된 체결가로 평가 가능하지만 주문 신선도 검사는 계속 거부함을 확인했다. 정상 조회의 원본 시각과 조회 시각도 별도로 보존했다. 인증된 운영 GET에서 /account, /positions, /cumulative-pnl 모두 valuationAvailable=true, valuationStatus=available과 보유 목록 표시를 확인했다. 실거래 주문을 테스트 목적으로 보내지 않았다. 앱 재배포는 필요 없으며 새로고침으로 적용된다.

복구 원본: /root/coinpilot-backups/20261008-valuation-timestamp. 실제 변경 해시는 deployment-manifest.json, 개인 금액을 제외한 운영 결과는 production-check.json에 있다.

기준 문서: https://docs.upbit.com/kr/reference/list-tickers — 현재가 API는 요청 시점의 티커 스냅샷을 반환하고, 최근 체결 시각은 별도 필드다.
