# CoinPilot iOS·macOS 기능 검증 기록

검토일: 2026-10-05, 한국 시간. 상태: **진행 중 — 전체 기능의 최종 앱 검증은 아직 끝나지 않았다.**

목표는 iOS 앱과 macOS 앱에서 사용자가 현재 상태를 이해하고, 필요한 기능에 도달하며, 입력한 값대로 작업을 마칠 수 있는지 확인하는 것이다. 인증·금액·갱신·입력·창 구성 문제에 더해, 실제 실행에서 발견한 iOS 자동 갱신 중단과 키보드 포커스 문제, 캔들 시각·첫 자산 기록 표시를 수정하고 재확인했다. 이 작업에서 전체 Node 테스트 1,292개와 캔들 시각 수정 후 Swift Store 52개 시나리오가 통과했고, 두 플랫폼의 앞선 clean full build도 성공했다. 이후 조건 주문·프리셋 안내와 병행 작업의 서버 연결 의존성까지 함께 복사한 **고정 QA 사본**으로 두 플랫폼 빌드와 회귀 검증을 다시 진행 중이다. 복사 시점의 원본 차이는 없었으나 이후 공유 저장소 변경은 이 검증에 포함되지 않는다. 마지막 수정의 빌드·화면 확인과 전체 기능 검증은 미완료다.

## 범위와 완료 기준

- 연결·인증 → 홈 → 주문 → 자산 → 시장 → 더보기의 모든 진입점을 확인한다.
- 정상 응답, 자료 없음, 일부 조회 실패, 오래된 시세, 권한 제한, 서버 전환, 재시작을 구분한다.
- KRW와 USDT의 표시 단위·최소 금액·소수 금액이 화면에서 요청, 계산, 저장, 재조회까지 유지되는지 확인한다.
- 주문은 확인 화면과 결과를 대조하고 중복 요청·미확정 결과가 다음 주문에 미치는 영향을 확인한다.
- iOS의 키보드·터치·작은 화면과 macOS의 창·시트·키보드 조작을 각각 실행한 앱에서 확인한다.
- 마지막 수정 소스의 테스트와 빌드가 통과하고, 아래 기능표의 미확인 항목에 결과와 근거가 채워져야 전체 완료로 판단한다.

작업 저장소는 `coin-automandation`이며, 이 검토를 시작할 때 확인한 브랜치는 `agent/arch-deepening-ws1`이었다. 기존 및 동시 작업의 변경이 함께 있으므로 Git 전체 diff를 이번 네이티브 검증의 변경으로 간주하지 않는다. 이 기록은 관찰한 문제, 관련 소스, 확인된 검증 결과만 다룬다.

검증 도중 같은 저장소의 별도 채팅 **「변경사항 통합 및 TestFlight 배포」**에서 AWS 자동 연결·Main 통합·TestFlight 요청에 따른 작업이 진행됐다. 해당 변경을 덮어쓰지 않고 보존했다. 처음에는 이전 Store·프로젝트 설정과 최신 Views를 묶은 부분 QA 사본을 만들었으나, Views에 포함된 서버 연결 UI가 새 Store의 `usesManagedServerConnection`에 의존해 두 플랫폼 빌드가 실패했다. 이는 서로 다른 시점의 파일을 선택한 QA 사본 구성 오류이며, 현재 저장소 전체의 빌드 실패로 해석하지 않는다. [Mac 실패 로그](mac-partial-snapshot-failure.log)와 [iOS 실패 로그](ios-partial-snapshot-failure.log)를 별도로 보존했다.

## 실제 실행에서 확인한 자동 갱신과 입력

iOS의 자동 갱신 중단은 시세 서버가 아니라 앱 생명주기 전달 문제였다. UIKit의 `UIHostingController`로 열린 화면에서 UIKit은 전경 활성(`activationState = 0`)이었지만 SwiftUI의 `scenePhase`는 `background`로 남아 있었다. `SceneDelegate`의 활성·비활성·배경 콜백을 ObservableObject로 전달하고 SwiftUI 환경에 명시적으로 주입했다. 원인 진단용 NSLog는 소스에서 제거했다.

수정 후의 [runtime-proof.json](runtime-proof.json), [수정 전 로그](ios-lifecycle-before.stderr.log), [수정 후 로그](ios-lifecycle-after.stderr.log), [QA HTTP 기록](qa-http.jsonl)에서 다음을 확인했다.

- 전경에서 계좌를 약 30초마다 다시 조회했다. 수동 동작에 따른 짧은 간격도 기록되어 있으므로 모든 요청 간격이 30초라는 뜻은 아니다.
- 한국 시간 18:20:12부터 18:22:49까지 배경 상태에서 계좌 요청이 **0건**이었다.
- 전경 복귀 후 첫 계좌 GET은 **0.057초** 뒤 도착했다.
- Mac에서 1,000원 모의 입금 후 iOS의 다음 계좌 조회는 **9.04초** 뒤 도착했고 화면 잔액은 **1,001,000원**으로 자동 갱신됐다. 이는 한 번의 관찰값이며 갱신 지연 상한을 뜻하지 않는다.

숫자 필드를 재탭하면 키보드가 닫히는 문제는 부모 뷰의 `simultaneousGesture`가 필드 탭도 받아 키보드를 내리는 동작으로 재현했다. 호출과 사용하지 않는 래퍼를 제거했다. 수정 전 12,000원 입력 후 재탭에서 키보드가 닫혔고(23·24), 수정 후 같은 값·동작에서 키보드를 유지했다(35·36). 이어 iOS 앱의 확인 화면에서 **12,000원 모의매수**를 실행했고 잔액 **989,000원**을 확인했다(37·38).

`부분 확인`은 진입 또는 일부 정상 동작을 관찰했다는 뜻이다. `미확인`은 이 검토에서 해당 조작을 실행하지 못했다는 뜻이다. API·Store 테스트가 있는 기능도 최종 앱 화면의 조작성까지 확인한 것으로 표시하지 않는다. 아래 확인 결과는 각 캡처·실행 당시 수정본의 결과이며, 마지막 조건 주문·프리셋 피드백 변경까지 반영한 전체 재검증을 의미하지 않는다.

## 남은 작업과 재개 방법

1. **통합 QA 사본의 회귀·빌드와 마지막 안내 화면을 확인한다.** `/Users/kimminkyu/Library/Caches/CoinPilotNativeQA-01a1096e/`의 `App`은 의존성을 함께 복사한 입력 사본, `mac`과 `ios`는 플랫폼별 결과 경로다. 사본 17개 해시를 기준으로 새 회귀·종료 코드·빌드 결과를 확인한다. 원본이 다시 변경되면 이미 실행한 검증에 포함시키지 말고 변경 범위를 다시 판단한다. 화면 제어가 복구되면 조건 주문 오류 설명, 확인 금액·점수·종목 수, 프리셋 적용 결과, 확인창 취소 후 이전 피드백 유지를 실제 화면에서 확인한다. 접근성 트리 일부 조회 이후에도 클릭이 `elementHasNoFrame`으로 실패해 마지막 GUI 확인은 미완료다.
2. **최종 앱을 합성 QA 서버에 연결한다.** [runNativeQA.mjs](../../../../mobile/scripts/runNativeQA.mjs)는 임시 저장소, 합성 거래자, 비활성화된 AI 제공자를 사용한다. 현재 지정 포트는 `39471`이다. 재시작이 필요하면 먼저 이 세션 서버의 소유권과 포트를 확인하고 세션의 managed-process helper로 실행한다. 사용자 서버나 다른 작업의 프로세스를 종료하지 않는다.
3. **iOS의 미확인 탭·하위 화면을 이어간다.** 현재 UI 상태와 접근성 트리를 다시 읽는다. DeviceHub의 탭 좌표 문제는 앱 탭이 고장났다는 증거가 아니며, 실패한 입력을 성공으로 기록하지 않는다. 가능한 접근성 연결 흐름을 사용하고, 홈·자산·탐색·더보기의 직접 탭 전환 완료 여부를 따로 기록한다.
4. **미확인 분기를 순서대로 확인한다.** 조건 주문의 정상 실행·추천/묶음 주문·부분 매도, 모의 출금/초기화, 유효한 새 토큰 저장·로그아웃, iOS 모드 전환·음수 튜닝·자동매매 control, 오프라인 재생을 우선한다. Mac의 모드 불일치 복구·잘못된 토큰 취소·합성 자동매매 시작/중지는 확인됐으므로 해당 완료 기록을 다시 미확인으로 돌리지 않는다. 일반 흐름이 확인된 화면도 오류·빈 자료·오래된 자료·재시도 분기가 자동으로 확인된 것은 아니다.
5. **마지막 변경에 해당하는 검증만 보강한다.** Store 재현 명령은 `npm --prefix mobile run test:store`다. 네이티브 빌드 진입점은 `ios:build:sim`, `ios:build:mac`이다. 원본 빌드 설정에 개인 연결 정보가 있을 수 있으므로 QA 고정 사본과 합성 설정을 유지한다. Node 검증은 저장소 요구 버전인 24.21 계열에서 실행하고 실행 시점·명령·소스·결과를 함께 기록한다.
6. **실기기와 외부 서비스 범위를 별도 기록한다.** iPhone 실기기 설치·실행, 장시간 서버 갱신, 외부 뉴스·AI 서비스 가용성, 실제 거래소 주문·정산은 이 작업에서 확인하지 않았다. 배포·TestFlight도 이 검증 작업의 수행 범위가 아니며, 별도 배포 채팅의 진행·결과와 구분한다. 수행한 범위만 결과에 추가한다.

이 검증은 사용자가 기능을 이해하고 조작할 수 있는지와 데이터 계약의 정확성을 다룬다. 자동매매의 수익성, AI 의견의 예측력, 장기 서비스 안정성은 이 결과로 입증되지 않는다.
