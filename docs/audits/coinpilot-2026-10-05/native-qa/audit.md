# CoinPilot iOS·macOS 기능 검증 기록

검토일: 2026-10-05, 한국 시간. 상태: **진행 중 — 전체 기능의 최종 앱 검증은 아직 끝나지 않았다.**

목표는 iOS 앱과 macOS 앱에서 사용자가 현재 상태를 이해하고, 필요한 기능에 도달하며, 입력한 값대로 작업을 마칠 수 있는지 확인하는 것이다. 발견한 인증·금액·갱신·입력·창 구성 문제는 소스에 반영했다. 최종 Swift Store 테스트는 51개 시나리오를 통과했다. 마지막 통화 표시 수정 이후의 두 플랫폼 빌드와 화면 재검증은 이 문서 작성 시점에 진행 중이다.

## 범위와 완료 기준

- 연결·인증 → 홈 → 주문 → 자산 → 시장 → 더보기의 모든 진입점을 확인한다.
- 정상 응답, 자료 없음, 일부 조회 실패, 오래된 시세, 권한 제한, 서버 전환, 재시작을 구분한다.
- KRW와 USDT의 표시 단위·최소 금액·소수 금액이 화면에서 요청, 계산, 저장, 재조회까지 유지되는지 확인한다.
- 주문은 확인 화면과 결과를 대조하고 중복 요청·미확정 결과가 다음 주문에 미치는 영향을 확인한다.
- iOS의 키보드·터치·작은 화면과 macOS의 창·시트·키보드 조작을 각각 실행한 앱에서 확인한다.
- 마지막 수정 소스의 테스트와 빌드가 통과하고, 아래 기능표의 미확인 항목에 결과와 근거가 채워져야 전체 완료로 판단한다.

작업 저장소는 `coin-automandation`, 현재 브랜치는 `agent/arch-deepening-ws1`이다. 기존 및 동시 작업의 변경이 함께 있으므로 Git 전체 diff를 이번 네이티브 검증의 변경으로 간주하지 않는다. 이 기록은 관찰한 문제, 관련 소스, 확인된 검증 결과만 다룬다.

## 확인한 결과와 근거

| 확인 종류 | 현재 결과 | 근거와 해석 |
|---|---|---|

| 추가 변경 관련 Node 테스트 | 140/140 통과 | LIVE 계좌·실보유량 수정 후의 집중 실행 결과. 전체 Node 재실행 결과와 구분한다. |
| 전체 ESLint | 통과 | 이번 작업의 도구 실행 기록. 앱 종료로 이전 임시 로그가 사라져 대화 기록을 근거로 보존한다. |
| 최종 Swift Store | **51개 시나리오 통과** | [store-final.log](store-final.log). 마지막 통화 기호 수정이 포함됐으며 테스트 시점 소스와 [source-manifest.json](source-manifest.json)의 일치를 확인했다. |
| iOS Simulator 최종 빌드 | **대기** | 이전 수정본 빌드는 성공했다. 마지막 통화 기호 수정 후 재빌드가 앱 종료로 중단돼 다시 빌드 중이다. 최종 로그가 확인되기 전 성공으로 올리지 않는다. |
| macOS 최종 빌드 | **대기** | 위와 동일. 고정된 빌드 사본에서 다시 빌드 중이다. |
| macOS 실제 조작 | 일부 확인 | 홈·주문 입력·10,000원 모의매수·더보기→설정→서버 편집 진입을 확인했다. 편집 시트가 좁은 문제를 발견해 수정했고 최종 시트 재확인은 남아 있다. |
| iOS Simulator 실제 조작 | 일부 확인 | 홈·주문 화면 캡처와 탭 진입을 확인했다. 선택 종목 복원과 최신 BTC 시세 표시를 중간 수정본에서 확인했다. 키보드 포커스와 모든 하위 화면의 최종 재확인은 남아 있다. |
| iPhone 실기기 | 미확인 | Simulator 결과로 실기기의 설치·터치·키보드·접근성 검증을 대체하지 않는다. |
| 실계좌 거래·정산 | 수행하지 않음 | 이번 상호작용 검증은 합성 자료와 모의 주문을 사용했다. 거래소 체결·잔고·정산 성공을 입증하지 않는다. |

위 전체 Node·집중 Node·ESLint의 이전 로그는 앱 종료로 임시 경로에서 사라졌다. 확인한 실행 결과를 적었으며 존재하지 않는 로그 링크를 제공하지 않는다. 이전 [사용 경험 개선 기록](../../coinpilot-2026-10-05-usefulness/README.md)과 [verification.json](../../coinpilot-2026-10-05-usefulness/verification.json)에 남은 1,284개 실행의 실패·정체 결과는 그 시점의 기록이다. 이후 1,290개 통과 결과와 실행 시점이 다르며, 어느 쪽도 마지막 추가 수정 이후의 전체 실행으로 바꾸어 해석하지 않는다.

## 기능별 확인 범위

`부분 확인`은 진입 또는 일부 정상 동작을 관찰했다는 뜻이다. `대기`는 마지막 수정본으로 직접 조작하지 못했다는 뜻이다. API·Store 테스트가 있는 기능도 최종 앱 화면의 조작성까지 확인한 것으로 표시하지 않는다.

| 사용자 기능 | 자동·소스 확인 | iOS 실행 화면 | macOS 실행 화면 | 남은 확인 |
|---|---|---|---|---|
| 시작·서버 연결·토큰·권한 | Store 및 인증 회귀 | 홈 진입 확인 | 홈 진입 확인 | 오류 복구·토큰 교체·재시작을 최종 앱에서 다시 확인 |
| 모의투자·실거래 작업공간 전환 | 늦은 응답 격리·서버 모드 계약 | 대기 | 대기 | 전환 중 화면·진행 상태와 모드 불일치 안내 |

## 남은 작업과 재개 방법

1. **최종 빌드 결과를 기록한다.** 앱 종료 뒤 사라진 임시 빌드 대신 `/Users/kimminkyu/Library/Caches/CoinPilotNativeQA-01a1096e/`의 고정 사본을 사용 중이다. `App`은 빌드 입력 사본, `mac`과 `ios`는 플랫폼별 빌드 결과 경로다. 계획된 로그 이름은 `mac-final-build.log`, `ios-final-build.log`이며 성공 종료와 최종 소스 일치를 확인한 뒤 위 표를 갱신한다.
2. **최종 앱을 합성 QA 서버에 연결한다.** [runNativeQA.mjs](../../../../mobile/scripts/runNativeQA.mjs)는 임시 저장소, 합성 거래자, 비활성화된 AI 제공자를 사용한다. 현재 지정 포트는 `39471`이다. 재시작이 필요하면 먼저 이 세션 서버의 소유권과 포트를 확인하고 세션의 managed-process helper로 실행한다. 사용자 서버나 다른 작업의 프로세스를 종료하지 않는다.
3. **현재 창 상태를 다시 읽고 UI 검증을 이어간다.** 이전 화면 제어에서 Mac 잠금 상태가 보고됐다. 앱 재시작 뒤 실제 상태를 다시 확인해야 한다. 클릭·입력을 실행할 수 없는 동안의 빌드나 캡처만으로 조작 성공을 기록하지 않는다.
4. **주문·설정 입력부터 재확인한다.** iOS 금액 필드의 포커스, 소수 키보드, 음수 튜닝, 완료 버튼, 100% 매도 수량을 확인한다. macOS 서버·토큰·튜닝·종목 선택 시트의 폭, 취소·Esc, 창 재열기를 확인한다. 그다음 기능표의 더보기 하위 화면을 순서대로 채운다.
5. **마지막 변경에 해당하는 검증만 보강한다.** Store 재현 명령은 `npm --prefix mobile run test:store`다. 네이티브 빌드 진입점은 `ios:build:sim`, `ios:build:mac`이다. 원본 빌드 설정에 개인 연결 정보가 있을 수 있으므로 QA 고정 사본과 합성 설정을 유지한다. Node 검증은 저장소 요구 버전인 24.21 계열에서 실행하고 실행 시점·명령·소스·결과를 함께 기록한다.
6. **실기기와 외부 서비스 범위를 별도 기록한다.** iPhone 실기기 설치·실행, 장시간 서버 갱신, 외부 뉴스·AI 서비스 가용성, 실제 거래소 주문·정산, 배포·TestFlight는 현재 확인되지 않았다. 수행한 범위만 결과에 추가한다.

이 검증은 사용자가 기능을 이해하고 조작할 수 있는지와 데이터 계약의 정확성을 다룬다. 자동매매의 수익성, AI 의견의 예측력, 장기 서비스 안정성은 이 결과로 입증되지 않는다.
