# 실거래 시작 실패 후속 점검

검토일: 2026-10-05, 한국 시간. 앱과 서버의 시작 경로 수정은 반영했으나, **현재 전략은 수익 검증을 통과하지 못해 실거래 자동매매가 정지 상태다.** 실제 자동매매 시작 성공이나 주문·체결 완료를 주장하지 않는다.

## 반영한 수정

1. 과거 시세 수집이 짧거나 빈 페이지, 중복 페이지, 잘못된 시각을 정상 자료처럼 반환하지 않도록 유지 중인 엄격한 수집 경로로 통합했다. 빠진 분을 합성하거나 시간을 건너뛰지 않는다.
2. 검증 보고서의 코인 목록, 실제 투자 대상, 코인별 결과가 기준 통화와 대상별로 정확히 일치하도록 검사한다. 다른 코인·누락·중복 결과로 실제 투자를 허용하지 않는다.
3. 실거래 실행·시작 준비 중 대상·포지션 설정 변경을 막는다. `ALL` 조회를 기다리는 동안 시작되면 적용 직전에 다시 거부한다. 혼합 설정 요청도 대상 검사 실패 전에 RSI·투자 비율을 변경하지 않는다.
4. 보고서 갱신은 현재 서버 설정과 현재 투자 대상의 전용 snapshot을 사용한다. 처음 부팅한 환경변수와 거래량 상위 코인으로 보고서가 바뀌지 않는다. snapshot에는 허용한 검증 필드만 기록하며, 권한은 `0600`이고 완료·실패 후 해당 임시 파일만 정리한다.
5. 시작·중지 응답이 앱 새로고침으로 사라지는 네이티브 수정을 TestFlight 21번으로 배포했다.

운영 서버에는 실제 배포 원본을 읽고 해시를 확인한 일곱 파일의 제한된 패치를 반영했다. 무관한 자동 복구 코드를 추가하지 않았으며, 전략 설정과 시작 조건을 낮추지 않았다. 백업은 `/root/coinpilot-backups/20261005-start-phase2-01a10bc0`에 있다. [배포 manifest](continuation-deployment-manifest.json), [정확한 패치](continuation-deployed.patch), [운영 읽기 결과](continuation-verification.json)를 보존했다.

배포 중 기존 자동 갱신 보고서의 대상이 `KRW-XRP,KRW-BTC,KRW-POD`로 바뀐 것도 읽기로 확인했다. 이것은 실제 설정인 BTC·ETH·XRP와 다르므로 새 검사는 시작을 거부했다. 현재 설정의 세 코인으로 공개 시세 검증을 다시 실행하여 **2026-10-05 21:14:02 한국 시간**에 보고서를 교체했다. 최종 읽기에서 대상·설정 불일치 오류는 없고 `confidence_gate_failed`로 차단됨을 확인했다. 이번 작업에서 실제 운영 시작 요청을 보내지 않았다.

## 원본 시세와 전략 결과

수집 전에 기간을 90일 분량, 투자 설정을 현재 값, 대상을 BTC·ETH·XRP로 고정했다. 동일 종료 시각 이전의 원본 1분봉을 시장마다 129,600개 수집했다. 누락된 캔들이 있어 실제 경과 기간은 90일보다 조금 길 수 있다.

| 코인 | 원본 시간 공백 | 구간별 진단 종료 거래 | 비용 반영 모의 계좌 수익률 | 평균 거래 수익률 |
| --- | ---: | ---: | ---: | ---: |
| BTC | 47곳 | 50회 | -0.2381% | -0.2384% |
| ETH | 344곳 | 56회 | -0.2942% | -0.2631% |
| XRP | 31곳 | 78회 | -0.3477% | -0.2232% |

이 결과는 같은 설정으로 연속 구간을 나누어 계산한 **진단 자료**다. 실제 계좌 수익률이나 체결 기록이 아니며 `promoted=false`를 유지한다. ETH의 경계 미청산 포지션 하나는 미확인으로 제외했다. 세 코인의 평균 거래 수익률 신뢰 하한도 모두 음수였다. [원본 품질](long-window-quality.json)과 [진단 결과](long-window-diagnostic.json)에 근거를 저장했다. 대용량 원본은 캐시에 보존했다.

성과를 보지 않고 가장 최근의 공통 연속 구간을 골랐을 때는 세 시장 모두 936개였다. 범위는 **2026-10-05 04:56–20:31 한국 시간**이다. 최소 2,000개보다 적어 [고정 설정 검증](latest-common-fixed-report.json)이 세 시장 모두 미통과했다. 좋은 결과가 나오는 구간을 찾아 보고서로 교체하지 않았다.

ETH와 XRP의 최근 누락 분은 API를 다시 조회해도 응답에 없었다. [재조회 결과](gap-readback.json)를 보존했다. 업비트는 해당 분에 거래가 없으면 캔들을 생성하지 않는다고 안내한다. 이는 원본 API 공백을 진단하는 근거이며, 누락된 가격 경로를 임의로 채워 실거래 시작을 허용하는 근거는 아니다. [업비트 공식 분봉 문서](https://docs.upbit.com/kr/reference/list-candles-minutes)

## 앱 배포

TestFlight **1.0 (21)**의 archive, export/upload, Apple `VALID`, 기존 `CoinPilot Internal` 포함, `IN_BETA_TESTING`, 기존 테스터 1명을 실제 GET으로 확인했다. 배포 사본에는 Store·테스트 두 파일만 반영했으며, 서명·설정·개발용 비밀 파일 제외를 실제 IPA에서 확인했다. [배포 증거](testflight-build21.json)를 따른다.

사본의 Store 62개가 통과했고, IPA 배포 서명을 확인했다. 공유 프로젝트의 build number도 21로 맞춰 다음 자동 릴리스가 중복 21번을 선택하지 않도록 했다. 실기기 설치·실행·화면 확인은 수행하지 않았다.

## 테스트와 남은 범위

- 새 시작 경로·현재 설정 캡처·시장 결합·수집 회귀의 최종 순차 실행: **46/46 통과**.
- 시장 결합·관련 경로: **122/122 통과**. 갱신기·loader·수집: **29/29 통과**.
- 테스트가 실제 CLI를 실행할 때 HTTP·HTTPS·fetch를 차단한 상태에서도 현재 설정과 코인 목록, snapshot 출처가 정확한지 확인했다.
- 배포된 Node 24.21.0에서 정상·누락·중복·다른 통화 게이트 검사와 현재 설정 snapshot 캡처를 메모리 내 가짜 거래자로 확인했다. 실제 시작·주문은 0회다.
- 운영 읽기: LIVE 정지, 거래소 상태 확인 완료, 관리 포지션 0개, 기존 수동 보호 감시 유지, 서비스 준비 정상. 일곱 파일의 실제 SHA-256도 manifest와 일치했다.
- 전체 Node 실행은 당시 높은 호스트 부하에서 subprocess·IPC 시간 제한 실패가 발생했고, 실패한 테스트의 연결 정리 대기로 멈춰 이 작업 소유 실행만 중단했다. **전체 suite 통과는 주장하지 않는다.** 새 CLI 회귀는 테스트에 한해 60초 시작 제한과 실패 진단을 넣어 통과시켰다. 기존 coordinator 재시작 fixture도 제어한 시계와 항상 연결을 닫는 정리로 보강했으며, 해당 시계·상태 회귀는 통과했다. 실행 환경의 독립 프로세스 시간 제한 재검증은 별도 로그로 보존했다.

실제 자동매매 시작에는 현재 전략의 검증 미통과가 남아 있다. 원본 공백·거래 표본·비용 반영 손실을 감춘 보고서를 만들거나 기존 시작 조건을 우회하지 않았다. 이 작업은 Git 커밋·푸시를 하지 않았고 다른 작업의 변경을 보존했다.
